# Link simulator: a runtime, opt-in debug filter for forcing topology

Multi-hop routing, single-path forwarding and passive self-healing (ADR-0002) only execute when nodes are *not* all in direct radio range. On a bench — or any space too small to physically separate radios (e.g. one ~80 m² open room) — three boards all hear each other at one hop, so the forwarding and Next-Hop code paths never run and cannot be exercised or demonstrated. There is no YAML-only way to suppress reception: the `sx126x`/`sx127x` `on_packet` automation is observe-only, and the radio adapter delivers every received frame to `LoraMesh::on_radio_packet()` regardless.

**Decision:** add an opt-in, compile-time-gated debug feature, `link_sim`. When `link_sim: true`, the node maintains a small runtime blocklist of *immediate senders* (the `prev_hop` field) and drops any received packet whose `prev_hop` is on the list, at the very top of `on_radio_packet()` — before duplicate/seen handling — so a blocked neighbour leaves no trace, exactly as if it were out of range. The blocklist is controlled at runtime (`add_blocked_neighbor`, `clear_blocked_neighbors`, `get_blocked_neighbors_str`), intended to be wired to web-UI controls. When the config key is absent/`false`, the entire feature (state and code) is compiled out via `#ifdef LORA_MESH_LINK_SIM`, leaving zero RAM/flash cost in production builds.

**Why `prev_hop`, not `src_id`:** `prev_hop` is the radio-level transmitter and is rewritten on each Forward, so it models RF range correctly. Blocking Node C's `prev_hop` on Node A means A never hears C's HELLOs directly (no direct Route), yet still accepts C's traffic Forwarded by B (`prev_hop` = B), which is precisely the A↔B↔C chain needed to exercise multi-hop. Blocking by `src_id` would wrongly drop C's traffic even when Forwarded, defeating the test.

**Why runtime, not compile-time:** node IDs in the field are MAC-suffixed and unknown until boot, so the blocklist must be set by typing a neighbour's name read off its web UI. More importantly, runtime control lets a link be broken or restored *live*, which is the only way to exercise passive self-healing (ADR-0002): force A↔B↔C, confirm a 2-hop route, then change the blocklist and watch routes re-converge.

**Consequence:** this is a debug/test foot-gun — a misconfigured blocklist silently blackholes traffic. It is mitigated by being opt-in (default `false`), compiled out otherwise, logging every block/drop at `DEBUG`/`INFO`, and being documented here as a test aid only. It must never be enabled on production firmware. The blocklist capacity is a small fixed `std::array` (no heap), sized for bench topologies; overflow is ignored with a warning.
